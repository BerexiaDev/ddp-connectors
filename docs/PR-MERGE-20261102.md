# PR #13 / #16 integration

The integration preserves both commit histories and reconciles PR #16
(`89e3b04`, based on main `5c162fb`) with the consolidation/release branch
(`bd212bb`). The annotated `0.2.2` tag remains on `bd212bb`; these integration
changes are unreleased and do not change that published snapshot.

Conflict decisions:

- Keep pyproject-based packaging/version 0.2.2; the old setup.py 0.1.3 metadata
  and dependency list are superseded.
- Preserve PR #16's Informix `SELECT 1 FROM systables WHERE tabid = 1`, readable
  DataDirect/native errors, and `last_error`, including Oracle missing-schema
  feedback. Run those pings through the current shared retries and cleanup.
- Keep 0.2.2's explicit Latin-1/UTF-8 codecs for both outbound parameters and
  inbound characters. Do not restore per-value encoding guessing, a Latin-1
  fallback for a UTF-8 configuration, or the older unverified 1252/8859-6/1256
  codesets. Unsupported configurations continue to fail explicitly.
- Retain main's Oracle correlated `EXISTS` catalog query, including owner and
  table-owner scoping. Multiple indexes must not duplicate extracted columns.

Regression checks were added before resolving code: ping query correctness,
readable errors, clearing stale errors, retry exhaustion/recovery and resource
cleanup, and a real relational catalog query with multiple indexes and colliding
constraint names across owners. The new tests failed against the release
baseline and pass after integration. The complete source suite has 49 tests:
38 passed, with 11 live tests explicitly skipped when no database is configured.

SELECT-only live probes passed Informix ping, bound filtering and exact
ASCII/accent/apostrophe retrieval; Oracle ping, missing-schema feedback, error
clearing after recovery, and timestamp schema discovery. No retained Oracle
multi-index fixture was available; that case is covered by the in-memory
relational catalog regression. Existing databases and DDP core were not changed.

An independent review found no production blockers. It verified that the
encoding/connection methods and shared retry helpers were otherwise unchanged;
the one stale README encoding summary was corrected.

Clean wheel and sdist installs on Python 3.10 passed with both default and
consumer-constrained dependencies: four runs, each 39 passed and 10 Oracle/
Informix fixture-writing tests skipped. PostgreSQL integration ran against a
new disposable instance. `pip check` and strict Twine metadata checks passed
for both profiles. GitHub's Python 3.10/3.11/3.12 checks gate the PR merge.
